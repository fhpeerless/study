1 为什么需要配置密钥？

2021 年 8 月起，GitHub 不再支持密码推送。 必须使用以下方式之一认证身份：

认证方式特点适合场景
Token Personal Access Token用 token 代替密码，有过期时间HTTPS 方式推送
SSH SSH 密钥配置一次后免密推送SSH 方式推送（推荐）
⚠️ 如果不配置

git push 时会提示输入用户名和密码，但输入 GitHub 账号密码会报错：Authentication failed

两种方式对比

HTTPS + Token
vs
SSH 密钥
对比项HTTPS + TokenSSH 密钥
远程地址格式https://github.com/...git@github.com:...
需要输入密码首次需要（可缓存）完全免密
配置复杂度简单稍复杂（一次配置）
安全性token 有过期时间密钥不过期
推荐度⭐⭐⭐⭐⭐⭐⭐⭐
2 方式一：配置 Personal Access Token

第步：在 GitHub 上生成 Token

登录 GitHub → 进入 Settings

点击右上角头像 → Settings

进入 Developer settings

左侧菜单最底部 → Developer settings

选择 Tokens (classic)

左侧菜单 → Personal access tokens → Tokens (classic)

点击 Generate new token (classic)

填写 Note（备注名，如 "我的电脑"）→ 选择 Expiration（过期时间，建议 90 天或 No expiration）

勾选权限范围

勾选 repo（完整仓库访问）→ 这是最重要的权限

⚠️ 注意

如果不勾选 repo，将无法 push 代码！

点击 Generate token → 立即复制

Token 只显示一次，务必立即复制保存！页面关闭后无法再看到。

⚠️ 重要

Token 类似密码，不要泄露给他人，不要提交到 Git 仓库！

第步：使用 Token 推送

方法 A：推送时输入（首次会提示）

首次推送
# 推送时会提示输入
git push
# Username: 输入你的 GitHub 用户名
# Password: 粘贴刚才复制的 Token（不是账号密码！）

方法 B：把 Token 嵌入远程 URL（方便但要注意安全）

Token 嵌入 URL
# 格式：https://git:TOKEN@github.com/用户名/仓库名.git
git remote set-url origin https://git:你的Token@github.com/用户名/仓库名.git

# 之后 git push 就不需要再输密码了
git push

方法 C：缓存凭据（推荐，安全且方便）

缓存 Token
# Windows 缓存（永久保存，除非手动清除）
git config --global credential.helper manager

# 或临时保存 1 小时
git config --global credential.helper "cache --timeout=3600"

# 首次 push 输入用户名和 Token 后，之后自动填充
3 方式二：配置 SSH 密钥（推荐）

第步：检查是否已有 SSH 密钥

检查现有密钥
# 检查是否有现有密钥文件
ls ~/.ssh

# 如果显示 id_ed25519 和 id_ed25519.pub 说明已有密钥
# 如果显示 "No such file" 说明需要生成新密钥

第步：生成 SSH 密钥

生成密钥（推荐 ed25519）
# 生成 ed25519 类型密钥（推荐，更安全更快）
ssh-keygen -t ed25519 -C "你的邮箱@example.com"

# 一路回车即可（默认路径、空密码）
# 出现提示时：
# Enter file in which to save key: 直接回车（默认路径）
# Enter passphrase: 直接回车（不设密码，方便日常使用）
# Enter same passphrase again: 直接回车
💡 老系统不支持 ed25519？

用 RSA 替代：ssh-keygen -t rsa -b 4096 -C "邮箱"

第步：启动 SSH 代理并添加密钥

启动 ssh-agent
# 启动 SSH 代理
eval "$(ssh-agent -s)"

# 将私钥添加到代理
ssh-add ~/.ssh/id_ed25519

第步：复制公钥

查看并复制公钥
# 显示公钥内容，全部复制
cat ~/.ssh/id_ed25519.pub

# Windows 也可用 clip 命令直接复制到剪贴板
cat ~/.ssh/id_ed25519.pub | clip

# 公钥内容类似：
# ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... 你的邮箱@example.com
⚠️ 注意区分

私钥 (id_ed25519)：绝对不能分享，留在本地

公钥 (id_ed25519.pub)：需要添加到 GitHub

第步：将公钥添加到 GitHub

登录 GitHub → Settings

点击右上角头像 → Settings

进入 SSH and GPG keys

左侧菜单 → SSH and GPG keys

点击 New SSH key

右上角绿色按钮 → New SSH key

填写信息

Title：备注名（如 "我的电脑"）

Key type：Authentication Key

Key：粘贴刚才复制的公钥内容

点击 Add SSH key

可能需要输入 GitHub 密码确认

第步：测试 SSH 连接

测试连接
# 测试 SSH 连接 GitHub
ssh -T git@github.com

# 第一次会提示是否信任，输入 yes 回车
# 成功后会显示：
# Hi 用户名! You've successfully authenticated, but GitHub does not provide shell access.
✅ 成功标志

看到 "Hi 用户名! You've successfully authenticated" 就说明 SSH 配置成功！

4 关联远程仓库

根据认证方式选择远程地址

认证方式远程地址格式
HTTPS + Tokenhttps://github.com/用户名/仓库名.git
SSH 密钥git@github.com:用户名/仓库名.git

场景 A：新项目首次关联远程

本地已有项目 → 关联远程
# 1. 进入项目目录，初始化 Git
cd my-project
git init

# 2. 添加文件并首次提交
git add .
git commit -m "初始提交"

# 3. 关联远程仓库（二选一）
# SSH 方式（推荐）
git remote add origin git@github.com:用户名/仓库名.git
# 或 HTTPS 方式
git remote add origin https://github.com/用户名/仓库名.git

# 4. 首次推送（-u 设置上游关联）
git push -u origin main

场景 B：克隆已有项目

从远程克隆到本地
# SSH 方式（推荐，配置好密钥后免密）
git clone git@github.com:用户名/仓库名.git

# 或 HTTPS 方式
git clone https://github.com/用户名/仓库名.git

# 克隆后自动关联远程，直接 git push 即可

场景 C：切换认证方式

从 HTTPS 切换到 SSH（或反过来）
# 查看当前远程地址
git remote -v

# 切换到 SSH 方式
git remote set-url origin git@github.com:用户名/仓库名.git

# 切换到 HTTPS 方式
git remote set-url origin https://github.com/用户名/仓库名.git

场景 D：本地空目录 + 远程有文件 + Token 认证（重点）

这是最常见的场景：本地文件夹是空的，GitHub 仓库已有内容，已有 Token，想绑定后正常使用 git add / commit / push。

⚠️ 关键点

本地空目录直接 git init 后关联远程还不够——必须先 pull 拉取远程文件到本地，否则本地没有远程的历史记录，push 时会冲突！

三个层次的理解：init / remote add / pull 各做什么？

操作作用比喻
git init把当前目录变成 Git 仓库（创建 .git 文件夹）开了一家店
git remote add origin URL记录远程地址（保存在 .git/config 里），只是"通讯录"记录记下总部的地址
git pull / git push -u真正拉取数据 / 建立分支关联和总部对接上业务
💡 所以完整的"绑定"需要三步

1. git init — 当前目录变成 Git 仓库

2. git remote add origin URL — 记录远程地址（只是个"通讯录"）

3. git pull origin main — 真正从远程拉取数据，建立关联

⚠️ 如果不执行 git init 直接 git remote add

会报错 fatal: not a git repository —— 因为还没有 .git 文件夹，Git 不知道往哪里保存这个远程地址。

完整操作流程
# ====== 第步：进入空目录，初始化 Git ======
cd E:\项目路径\my-project
git init # 把当前目录变成 Git 仓库（创建 .git 文件夹）

# ====== 第步：用 Token 关联远程仓库 ======
# 格式：https://git:TOKEN@github.com/用户名/仓库名.git
# 把 你的Token、用户名、仓库名 替换成实际值
git remote add origin https://git:你的Token@github.com/用户名/仓库名.git

# ====== 第步：拉取远程文件到本地 ======
# 这一步会把远程仓库的所有文件下载到本地目录
git pull origin main

# 如果远程分支是 master，用：git pull origin master
# 如果报错 refusing to merge unrelated histories，加参数：
# git pull origin main --allow-unrelated-histories

# ====== 第步：设置上游关联（以后直接 git push 即可）======
git branch --set-upstream-to=origin/main main
# 如果本地分支是 master：
# git branch --set-upstream-to=origin/master master

# ====== 第步：验证绑定成功 ======
git remote -v     # 查看远程地址
git status      # 应显示 On branch main, up to date
ls              # 应能看到远程仓库的文件

# ====== 现在可以正常使用 git 操作了！ ======
# 修改文件后：
git add .       # 添加修改到暂存区（现在生效了！）
git commit -m "你的提交说明"
git push        # 推送到远程

场景 D 补充：不想暴露 Token 在 remote URL 中？

用普通 HTTPS 地址关联，配合凭据缓存，Token 会安全存储：

安全方式（Token 不留在 URL）
# 1. 用普通 HTTPS 地址关联（不含 Token）
git remote add origin https://github.com/用户名/仓库名.git

# 2. 设置凭据缓存（Windows 用 manager）
git config --global credential.helper manager

# 3. 拉取远程文件
git pull origin main

# 4. 首次 pull/push 会弹出输入框：
#    Username: 输入 GitHub 用户名
#    Password: 粘贴 Token（不是账号密码）
# 输入一次后，Windows 会记住凭据，以后免输入

# 5. 设置上游后正常操作
git branch --set-upstream-to=origin/main main
git add .
git commit -m "提交说明"
git push
✅ 两种方式对比

Token 嵌入 URL：简单直接，但 token 明文存储在 .git/config 中（可用 git remote -v 看到）

凭据缓存方式：更安全，Token 存在 Windows 凭据管理器中，不在 git 配置里暴露

5 Git 全局配置（首次必做）

配置用户名和邮箱

每次 commit 都会记录这些信息，必须配置：

全局配置
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"
💡 邮箱建议

用 GitHub 注册邮箱，这样提交记录会关联到你的 GitHub 账号

其他实用配置

# 设置默认分支名为 main（新版规范）
git config --global init.defaultBranch main

# 设置中文文件名正常显示
git config --global core.quotepath false

# 设置默认编辑器（可选）
git config --global core.editor "code --wait"

# 查看所有配置
git config --list

常见问题排查

问题1：Permission denied (publickey)

SSH 密钥未正确配置。检查：

1. 公钥是否已添加到 GitHub

2. 远程地址是否为 SSH 格式（git@github.com:...）

3. 运行 ssh -T git@github.com 测试

问题2：Authentication failed

Token 认证失败。检查：

1. Token 是否过期（GitHub Settings 重新生成）

2. Token 是否勾选了 repo 权限

3. 是否用的 Token 而非账号密码

问题3：fatal: not a git repository

当前目录不是 Git 仓库。需要 cd 进入项目目录，或运行 git init 初始化
