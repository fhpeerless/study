1 什么是 Git？

Git 是一个 分布式版本控制系统，用于追踪文件的变化，协作管理代码。

简单来说，它就像一个 "超级存档系统"，让你：

✅ 随时回退到之前的版本（后悔药）

✅ 多人同时开发互不干扰

✅ 记录每次修改的内容和原因

✅ 安全地尝试新功能，不影响主线

Git vs GitHub 的区别

对比项GitGitHub
是什么版本控制工具（软件）代码托管平台（网站）
运行在你的电脑上（本地）云端（远程）
需要安装吗需要下载安装注册账号即可
类似平台—Gitee、GitLab、Bitbucket
2 安装与配置

安装 Git

Windows 访问 git-scm.com 下载安装包，一路下一步即可

Mac 终端输入 brew install git

Linux 终端输入 sudo apt install git

首次使用必须配置

安装完成后，告诉 Git 你是谁（每次提交都会记录这些信息）：

终端 / Git Bash 
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"
✅ 验证配置

输入 git config --list 可查看所有配置

3 核心概念：三大区域

Git 有三个重要的工作区域，理解它们是学好 Git 的关键：

工作区
Working Directory
→ git add →
暂存区
Staging Area
→ git commit →
版本库
Repository

📦 工作区：你正在编辑的文件目录（你看到的文件夹）

📋 暂存区：准备提交但还没提交的文件（"购物车"）

🗄️ 版本库：已提交保存的快照记录（"已下单"）

生活类比：网上购物

Git 区域购物类比操作
工作区在商场挑选商品修改文件
暂存区加入购物车git add
版本库下单结算git commit
远程仓库送货到家git push
4 基本操作流程

创建仓库

方式一：新建项目 
# 创建项目目录
mkdir my-project
# 进入目录
cd my-project
# 初始化 Git 仓库
git init
方式二：克隆远程仓库 
git clone https://github.com/用户名/仓库名.git

日常操作四步走

标准工作流 
# 1. 查看文件状态（哪些文件被修改了）
git status

# 2. 将所有修改加入暂存区（注意 add 和 . 之间有空格）
git add .

# 3. 将暂存区的文件提交到版本库
git commit -m "提交说明：简单描述做了什么"

# 4. 将本地提交推送到远程仓库
git push

查看状态与历史

# 查看当前状态（最常用的命令）
git status

# 查看提交历史记录
git log --oneline --graph

# 查看文件具体修改了什么
git diff
💡 小贴士

git status 是你最好的朋友，随时用它查看当前状态！

6 分支管理

分支是 Git 最强大的功能。分支就像平行宇宙，你可以在不影响主线的情况下尝试新东西。

main 主线
━ ━ ━ ━
feature 新功能

分支操作命令

# 查看所有分支（* 号表示当前所在分支）
git branch

# 创建新分支
git branch feature-login

# 切换到指定分支
git checkout feature-login
# 或用新语法（推荐）
git switch feature-login

# 创建并切换（快捷方式）
git checkout -b feature-login
# 或
git switch -c feature-login

# 将指定分支合并到当前分支
git merge feature-login

# 删除已合并的分支
git branch -d feature-login

分支工作流程

团队协作标准流程 
# 1. 从 main 创建并切换到新分支
git checkout -b my-feature

# 2. 开发修改文件后，提交
git add .
git commit -m "完成功能开发"

# 3. 切回 main 并拉取最新代码
git checkout main
git pull

# 4. 合并你的分支到 main
git merge my-feature

# 5. 推送到远程
git push

# 6. 删除临时分支
git branch -d my-feature
7 远程仓库操作

关联远程仓库

# 添加远程仓库（origin 是远程仓库的别名）
git remote add origin https://github.com/用户名/仓库名.git

# 查看已关联的远程仓库
git remote -v

# 首次推送（-u 设置上游关联，以后直接 git push 即可）
git push -u origin main

推送与拉取

命令作用比喻
git push本地 → 远程上传代码
git pull远程 → 本地下载代码
git fetch获取远程更新（不合并）看看有什么新东西
⚠️ 重要提醒

每天开始工作前，先 git pull 拉取最新代码！

每次结束工作前，记得 git push 推送你的代码！

9 撤销操作（后悔药）

            

                
不同阶段的撤销

                

                    

                        
阶段命令效果

                        
                            
工作区修改了，还没 addgit checkout -- <file>丢弃修改

                            
已经 add，还没 commitgit reset HEAD <file>移出暂存区

                            
已经 commit，还没 pushgit reset --soft HEAD~1撤销提交，保留修改

                            
已经 pushgit revert <commit>创建反向提交

                        
                    

                

                

                    
⚠️ 注意

                    
git reset --hard 会永久删除未提交的修改，慎用！
